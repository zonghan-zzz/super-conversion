# 福格行为模型：从“为什么没行动”到具体修改

## 原理论

**B=MAP**：Behavior（行为）发生需要 Motivation（动机）、Ability（能力/容易程度）、Prompt（提示）在同一时刻共同满足条件。它是解释框架，不是三个数相乘得到行为概率或转化率的公式。[作者官网](https://www.behaviormodel.org/)

动机与容易程度存在补偿关系；动机随时间波动。作者区分感受、预期、归属三类动机，对应愉悦/痛苦、希望/恐惧、接纳/排斥。[Motivation](https://www.behaviormodel.org/motivation)

提高能力可以提供工具/资源、缩小目标行为，必要时提供训练；容易程度取决于当时最稀缺的资源。[Ability](https://www.behaviormodel.org/ability)

提示可以来自外部或日常情境。作者使用 Spark、Facilitator、Signal 三类提示，按动机和能力情境选择；早期 Trigger 后改称 Prompt。[Prompts](https://www.behaviormodel.org/prompts)

## FM-01｜绑定同一个人、同一个行为、同一个时刻

**应用规则**：把“提高转化”改写为“目标用户在某入口/设备下，完成某个可观测动作”。例如：来自比较文章的新用户，在预约页选择时间并成功提交。不能把“想了解”的动机当作“愿意付费”的动机。

**检查**：是否看见且理解下一步；此刻能否完成；是否认为值得做。可先查显性的提示与操作阻断，再查价值/信任。这是本 skill 的排查顺序，不是 MAP 规定的心理先后过程。

**验证**：分别记录入口曝光、动作开始、成功完成；心理归因用访谈或行为证据补充。

## FM-02｜动机不足：把任务收益讲具体

**信号**：抽象口号、只列功能、任务和承诺错位。

**应用**：标题写成目标任务的真实结果，紧邻必要证据，说明行动后会发生什么。三类动机用于提出研究问题，不自动生成恐惧或社会排斥文案。

**边界/验证**：优惠不是所有问题的答案；没有需求的人不应靠更多提示硬推。按钮点击上升而合格率下降时重新评估价值表达。

## FM-03｜能力不足：先消除最难的一步

以下为本 skill 的页面检查维度，不宣称是某一版本能力链的逐字清单：

| 资源/门槛 | 页面或流程检查 | 整改候选 |
|---|---|---|
| 时间 | 重复输入、需中断去找资料 | 删除非必要输入、保存进度、允许稍后补充 |
| 金钱/权限 | 总成本不清、无付款或采购权限 | 明示总价/条件，提供适合当前角色的报价或协作下一步 |
| 操作 | 小屏操作困难、错误后内容丢失 | 合适的输入控件，保留输入并支持就地修复 |
| 理解 | 术语多、选项不可比较 | 通俗标签、示例、同口径比较 |
| 流程熟悉度 | 必须学完复杂配置才能体验价值 | 合适模板、示例数据或更小的首次任务 |

**边界**：能力因时因人变化，不能推断用户“能力差”。删除必要资格信息可能损害质量；高风险操作确认不属于无效摩擦。官方当前能力页展示五因素图，早期材料常用六因素，未核实版本时不要混列成唯一标准。

**验证**：任务完成率、耗时、错误与恢复、合格率；截图无法验证的项目标为待检查。

## FM-04｜提示匹配状态

下表为三类提示的 UI 应用解释；用户状态未知时提出假设，不先入为主贴标签。

| 状态 | 提示类型 | 页面动作示例 |
|---|---|---|
| 容易做，但缺乏理由 | Spark | 在按钮附近补充相关可信的收益，连接明确动作 |
| 想做，但做起来难 | Facilitator | 提供简化入口、模板或预填；只有文案说“很简单”不够 |
| 想做且能够做 | Signal | 及时指出下一步，减少同级竞争提示 |
| 动机和能力都不足 | 不靠提示频次解决 | 重新选更有价值、更小且可完成的动作 |

**验证**：提示曝光后的任务完成与干扰/退出。提示不等于弹窗数量；主次 CTA 可以并存，不机械规定全页只有一个按钮。

## FM-05｜逐步衔接行为

**应用**：成功后给可理解的结果及自然下一步。可用于“先查看真实演示，再选择是否预约”，不能先骗取轻承诺，再暗中扩大授权。

**验证**：端到端完成率。微步骤增加可能降低整体效率，不能只看第一步点击提升。
